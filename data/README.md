# Committed data

Only small files live here. Raw inputs (about 4 GB) are read from `FLOOD_DATA_DIR`; see
`docs/adding-a-region.md` for the list and sources.

| File | What it is | Source | Licence | Referenced from |
|---|---|---|---|---|
| `lagos/hotspots.csv` | 20 locations repeatedly reported as flooded, with approximate settlement-centroid coordinates (WGS84, accurate to a few hundred metres) and the report that names each one | Compiled for this project from published studies and news reports (column `source`) | Compilation released under this repository's MIT licence | `validation.hotspots` in `regions/lagos.yaml` |
| `lagos/lga_boundaries.geojson` | Simplified outlines of the 20 Lagos Local Government Areas, used by the app and the figures | geoBoundaries gbOpen NGA ADM2 (source: GRID3), release built 2023-12-12, selected by overlap with the Lagos boundary with `python -m flood fetch-boundaries --region lagos` | CC BY 4.0. Attribution: geoBoundaries (Runfola et al. 2020) and GRID3 | `app.admin_units` in `regions/lagos.yaml` |

The model's own exposure table uses the admin units named in `data.admin_units`, read from
`FLOOD_DATA_DIR` and not redistributed here. Unit names are mapped to the geoBoundaries
spelling with `data.admin_units.rename`.

`app/data/lagos/` holds files generated by the `scenarios` stage for the deployed app
(downsampled zone grids, exposure tables, metadata and a copy of the boundary file above).
